# Phase 2c: File Attachments Design

**Date:** 2026-07-31  
**Status:** Approved

---

## Overview

Phase 2c adds file attachments to graphbrain. Uploading a file (image, PDF, or document) creates a first-class **file page** — a `pages` record that appears in the sidebar as a child of the page from which it was uploaded, plus a `files` record holding the storage path, MIME type, and extracted text.

File pages are navigable, linkable, and searchable like any other page. For PDFs and documents, text is extracted asynchronously after upload using Next.js `after()`, with a polling-based "Indexing…" status in the UI until extraction completes. Phase 4 will consume `extracted_text` for vector embeddings.

> **Deferred:** Folder/group creation UI (explicit "New Folder" action in sidebar) is out of scope for Phase 2c. The `pages.parent_id` hierarchy already supports nesting; users can organise file pages by uploading from within the appropriate parent page. Folder creation UI is a dedicated future phase.

---

## Supported File Types

| Type | Extensions | Extraction |
|------|-----------|------------|
| Image | jpg, jpeg, png, gif, webp, svg | None (`extraction_status = 'none'`) |
| PDF | pdf | `pdf-parse` → `extracted_text` |
| Word document | docx, doc | `mammoth` → `extracted_text` |
| Plain text | txt, md | Read as UTF-8 → `extracted_text` |
| Other | * | Stored as download only (`extraction_status = 'none'`) |

## Architecture

### Upload Flow

The browser uploads file bytes **directly to Supabase Storage** via a signed PUT URL — the Next.js server never proxies the bytes. After the upload completes client-side, a server action creates the page and file records, then schedules text extraction via Next.js `after()`.

```
Client                          Server Action              Supabase
  │                                   │                       │
  │── getUploadUrl(name,mime,ws) ────>│                       │
  │<─ { signedUrl, storagePath } ─────│                       │
  │                                   │                       │
  │── PUT bytes ──────────────────────────────────────────>   │
  │<─ 200 OK ─────────────────────────────────────────────    │
  │                                   │                       │
  │── createFilePage(...) ───────────>│                       │
  │                    INSERT pages + files (status=pending)  │
  │<─ { pageId } ─────────────────────│                       │
  │                                   │                       │
  │                         after() runs extraction           │
  │                         UPDATE files SET extracted_text,  │
  │                                    extraction_status='done'│
```

### File Page Model

Every uploaded file creates two records:

- **`pages`** — `title = filename`, `parent_id = uploading page's id`, `workspace_id`, `created_by`
- **`files`** — `page_id = new page id`, `workspace_id`, `storage_path`, `mime_type`, `extracted_text`, `extraction_status`

Navigating to the file page (`/workspace/[workspaceId]/page/[pageId]`) detects the `files` record and renders `FilePage` instead of `PageEditor`.

### Supabase Storage

- **Bucket:** `files` (private — RLS enforced via signed URLs)
- **Path format:** `{workspaceId}/{pageId}/{filename}`
- **Upload:** Signed PUT URL (60s expiry), generated server-side
- **Read:** Signed GET URL (1h expiry), generated server-side per request
- **RLS policy:** Bucket is private; all access goes through signed URLs generated by authenticated server actions

ALTER TABLE files
  ADD COLUMN extraction_status text NOT NULL DEFAULT 'pending'

`extraction_status` values:
- `pending` — PDF/doc/txt uploaded, extraction not yet complete
- `done` — `extracted_text` is populated
- `error` — extraction failed (file still usable as download)

## Server Actions (`src/lib/actions/files.ts`)

All actions use `'use server'` and `createClient()` from `@/lib/supabase/server`. All enforce workspace membership before operating.

### `getUploadUrl(filename, mimeType, workspaceId)`

Generates a signed PUT URL for direct browser-to-Storage upload.

- Validates user is authenticated and is a member of `workspaceId`
- Generates a unique `pageId` (UUID) to use as part of the storage path
- Calls `supabase.storage.from('files').createSignedUploadUrl(path)`
- Returns `{ signedUrl, storagePath, pageId }` — `pageId` is reserved for the subsequent `createFilePage` call

### `createFilePage(workspaceId, parentPageId, filename, storagePath, mimeType, reservedPageId)`

Creates the page + file records after a successful browser upload.

- Inserts `pages` record with the `reservedPageId`, `title = filename`, `parent_id = parentPageId`
- Determines `extraction_status`: `'pending'` for pdf/docx/doc/txt/md, `'none'` for images and others
- Inserts `files` record with `extraction_status`
- If either insert fails, cleans up the other record and the Storage object before throwing
- Schedules extraction via `after()` for `pending` files (see Extraction below)
- Calls `revalidatePath` for the parent page
- Returns `{ pageId }`

### `getFileRecord(pageId, workspaceId)`

Returns the `files` record for a given page. Used by the polling mechanism in `FilePage`.

- Validates workspace membership
- Joins `files` → `pages` → workspace_id check
- Returns `FileRecord | null`

### `retryExtraction(fileId, workspaceId)`

Re-triggers extraction for a file stuck in `pending` or `error` state.

- Validates workspace membership and file ownership
- Runs the same extraction logic as `after()` synchronously (blocking)
- Updates `extracted_text` and `extraction_status`
- Returns updated `FileRecord`

### `getSignedReadUrl(storagePath, workspaceId)`

Returns a signed GET URL (1h expiry) for rendering a file.

- Validates workspace membership
- Calls `supabase.storage.from('files').createSignedUrl(storagePath, 3600)`
- Returns `{ url }`

## Extraction Logic (runs inside `after()`)

```
1. Fetch file bytes from Supabase Storage using service-role client
2. Branch on mime_type:
   - application/pdf            → pdf-parse(buffer) → text
   - application/vnd.openxml... → mammoth.extractRawText({ buffer }) → text
   - application/msword         → mammoth (same)
   - text/plain, text/markdown  → buffer.toString('utf-8')
   - default                    → skip (status already 'none')
3. UPDATE files SET extracted_text = text, extraction_status = 'done'
   WHERE id = fileId
4. On any error:
   UPDATE files SET extraction_status = 'error' WHERE id = fileId
```

Libraries: `pdf-parse`, `mammoth` (both npm packages).

## Components

### `FileUploadButton` (`src/components/files/FileUploadButton.tsx`)

Client component rendered inside `PageEditor` below the block editor.

- Renders an "Attach file" button that opens a native `<input type="file">`
- On file selected:
  1. Calls `getUploadUrl` → receives signed URL + storagePath + reservedPageId
  2. PUTs file bytes to signed URL via `fetch`
  3. Calls `createFilePage` with the returned storagePath and reservedPageId
  4. On success: appends new file entry to a local list (optimistic), shows thumbnail or filename
  5. On any error: shows inline error message, no orphaned records (server action handles cleanup)
- Shows upload progress via `XMLHttpRequest` `progress` event
- Accepts multiple files sequentially (one upload at a time)

### `FilePage` (`src/components/files/FilePage.tsx`)

Client component that renders a file page. Receives `fileRecord` and `signedUrl` as props (fetched server-side on the page route).

**Rendering by type:**

| MIME prefix | Renders |
|-------------|---------|
| `image/` | `<img src={signedUrl} className="max-w-full rounded" />` |
| `application/pdf` | `<iframe src={signedUrl} className="w-full h-[80vh]" />` |
| `text/` | Extracted text in a `<pre>` / prose block |
| `application/vnd.openxml...` / `application/msword` | Extracted text in prose block |
| other | Download link only |

Always renders a download `<a href={signedUrl} download>` link regardless of type.

**Extraction status:**

- `pending` — shows "Indexing…" badge; polls `getFileRecord` every 3s, max 10 attempts; on `done` re-renders with extracted text; on timeout shows "Indexing unavailable" + "Retry" button that calls `retryExtraction`
- `error` — shows "Extraction failed" badge + "Retry" button
- `none` — no extraction badge shown
- `done` — renders `extracted_text` below the file preview

### `PageEditor` (modified)

Add below the existing `BlockEditor`:

```tsx
<FileUploadButton pageId={pageId} workspaceId={workspaceId} />
```

Also renders a list of existing child file pages (fetched server-side as part of the page route, passed as a prop).

## Page Route Changes

`src/app/(app)/workspace/[workspaceId]/page/[pageId]/page.tsx`:

1. After fetching the page, call `getFileRecord(pageId, workspaceId)`
2. If a `FileRecord` exists for this page → fetch signed read URL → render `FilePage`
3. If no `FileRecord` → render existing `PageEditor` (unchanged path)
4. Also fetch child pages that are file pages → pass as `fileAttachments` prop to `PageEditor`

## Error Handling

| Scenario | Handling |
|----------|---------|
| `getUploadUrl` fails | Inline error in `FileUploadButton`; no upload attempted |
| Storage PUT fails | Inline error; `createFilePage` never called; no orphaned records |
| `createFilePage` — page insert succeeds, files insert fails | Server action deletes the page record + Storage object before throwing |
| `createFilePage` — both inserts succeed, `after()` crashes | `extraction_status` stays `'pending'`; client polls 10× then shows "Retry" |
| PDF encrypted / malformed | `pdf-parse` throws → `extraction_status = 'error'`; file still downloadable |
| `mammoth` fails on corrupt DOCX | Same → `extraction_status = 'error'` |
| Signed read URL fetch fails on `FilePage` | "File unavailable" message with refresh button |
| Workspace membership check fails | 403-equivalent error thrown; client shows generic error |

## Testing

### Unit Tests (`src/__tests__/lib/actions/files.test.ts`)

Mock pattern: same as `databases.test.ts` — mock `@/lib/supabase/server` to return a chainable mock client.

- `getUploadUrl`: returns signed URL shape; throws if user not in workspace
- `createFilePage`: inserts page + file records; sets `extraction_status = 'none'` for images, `'pending'` for PDFs; deletes both records + Storage object if second insert fails (atomicity)
- `getFileRecord`: returns file record; returns null for wrong workspace
- `retryExtraction`: calls extraction logic; updates `extraction_status` to `'done'` on success, `'error'` on failure

### Component Tests (`src/__tests__/components/files/FilePage.test.tsx`)

- Renders `<img>` for image MIME type
- Renders `<iframe>` for PDF MIME type
- Renders extracted text for `extraction_status = 'done'`
- Renders "Indexing…" badge for `extraction_status = 'pending'`
- Renders "Extraction failed" + Retry button for `extraction_status = 'error'`

### E2E (`e2e/files.spec.ts`)

- Upload an image → new file page appears in sidebar under current page → navigate to it → image renders
- Upload a PDF → file page appears → "Indexing…" shown → (stub extraction) → extracted text renders
- Upload fails (server error stubbed) → error shown inline → no orphaned sidebar entry
